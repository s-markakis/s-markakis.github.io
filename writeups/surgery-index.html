Surgery on a
Running Network

Every one of these changes is something a network needs eventually — segmentation, re-addressing, a new core, IPv6, a vendor swap — and every one has to happen while people are using the network. This series is the order of operations that gets each done without an outage: additive first, reversible at every step, enforcement turned on last.

Surgery Migration Zero Downtime Cutover Rollback

Designing a network from scratch is the easy case; the hard case is changing one that is already carrying work and cannot stop. Each post here is a cutover: the starting point, the three rules (additive, reversible, enforce-last), the ordered steps with a rollback for each, the gotchas that lock people out, and a maintenance-window checklist. The companion series, Broken by Design, is what happens when a change is done the wrong way.

They are filed under the surgery category on the blog.

Moving the Gateways

Changing where the network routes

The riskiest live changes move the default gateway — done per subnet, with the old gateway kept warm.

03Pushing Routing to the EdgeMigrate from layer-2 access to routed access — each switch routing to the core — shrinking the spanning-tree failure domain one subnet at a time, with the old gateway as backup during each cut.7 min→ 04Replacing the Core Without DowntimeSwap an end-of-life core by running the new one in parallel, pairing them with FHRP and routing, moving uplinks one at a time, flipping the virtual gateway, and retiring the old only when idle.7 min→

Protocols & Vendors

Changing the technology underneath

Adding a protocol, crossing a major version, or swapping vendor — all without a big-bang weekend.
