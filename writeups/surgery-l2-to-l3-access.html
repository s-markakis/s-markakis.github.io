Surgery on a Running Network
Pushing Routing to the Edge

Your campus is one big layer-2 domain: every VLAN trunked from every access switch back to a central pair, spanning tree deciding the paths, and a single loop or a single core taking the whole site down. Routed access fixes that — each access switch becomes layer 3 and routes to the core — but the gateway for every subnet has to move from the core to the edge while people are using it. Here is how to do that one subnet at a time.

Surgery Migration Routed Access OSPF Spanning Tree Failure Domain

In layer-2 access, access switches are dumb: every VLAN is trunked up to a central router or core pair that holds all the gateways, and spanning tree picks which trunk forwards and which blocks. It is simple, but the whole campus is one broadcast domain and one spanning-tree instance — a loop anywhere, or a core failure, affects everything, and half your uplinks sit idle in blocking.

In routed access, each access switch is layer 3: it holds the gateways for its own subnets and routes to the core over a routing protocol, so there is no site-wide spanning-tree domain, every uplink is active (ECMP), and a fault is contained to one switch. The migration moves each subnet’s gateway from the core to the edge — which is a default-gateway change for its hosts — so it is done one subnet at a time, with the old gateway kept alive until the new one is proven.

The Cutover, Per Subnet

Build the routed underlay first, then move each subnet’s gateway to the edge one at a time — the old gateway stays as a backup until the new one is proven.

⚠ Gotcha — the gateway move is a client-affecting change

Moving a subnet’s gateway from the core to the access switch changes which device answers for the .1. If you just delete the core SVI and create the edge one, there is a gap. Keep both gateways live during the cut — an FHRP (VRRP/HSRP) virtual gateway that you move, or the core SVI left as a lower-priority backup — so hosts never lose their default gateway. Only remove the core’s copy once the edge gateway is proven. And watch the VLAN that spans two switches: it cannot be fully routed-access until it lives on one.

Takeaways

  1. Routed access shrinks the failure domain to one switch and makes every uplink active — no site-wide spanning tree.
  2. Build and prove the OSPF underlay first, carrying no user traffic, before any gateway moves.
  3. Migrate one subnet at a time, moving its gateway to the edge while keeping the core gateway as a backup.
  4. The gateway move is client-affecting — use FHRP or a retained backup SVI so no host loses its default route.
  5. A VLAN that spans two switches cannot go fully routed-access until it lives on one — plan those.
