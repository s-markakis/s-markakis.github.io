Cisco IOS
Πρωτη Επαφη

Η πρώτη σου ώρα σε ένα switch ή router Cisco. Δεν προϋποθέτουμε καμία προηγούμενη εμπειρία με IOS — ξεκινάμε από το καλώδιο console, μαθαίνουμε τα τρία command modes, τρέχουμε μόνο ασφαλείς εντολές μέχρι να νιώσεις σιγουριά, και μετά βάζουμε hostname, κωδικό, και πρόσβαση SSH από το μηδέν.

Cisco IOS CLI Console SSH Catalyst CCNA Beginner

Κάθε switch και router Cisco έρχεται με το ίδιο λειτουργικό γραμμής εντολών: το IOS (ή IOS-XE στον νεότερο εξοπλισμό — ίδιο CLI για ό,τι βλέπουμε σε αυτό το tutorial). Δεν υπάρχει Winbox, ούτε web wizard να βασιστείς. Το CLI είναι η συσκευή. Μάθε το μία φορά και ρυθμίζεις ένα Catalyst των 200 δολαρίων ή έναν core router των 20.000 με την ίδια muscle memory.

Αυτό το tutorial είναι για κάποιον που δεν έχει πληκτρολογήσει ποτέ εντολή σε συσκευή Cisco — φοιτητή CCNA, admin του MikroTik που περνάει απέναντι, ή τεχνικό που μόλις κληρονόμησε ένα rack από switch. Ξεκινάμε από το καλώδιο console, αφιερώνουμε πραγματικό χρόνο στα τρία command modes (αυτό που μπερδεύει τους πάντες στην αρχή), τρέχουμε μόνο read-only εντολές show μέχρι να εμπιστευτείς τον εαυτό σου, και κλείνουμε βάζοντας hostname, κωδικό, και λειτουργική πρόσβαση SSH. Στο τέλος θα μπορείς να ψαχουλεύεις με ασφάλεια οποιαδήποτε συσκευή Cisco σου δώσουν.

Προαπαιτουμενα
  • Ένα switch ή router Cisco (πραγματικό hardware, ή lab σε Packet Tracer / GNS3 / CML)
  • Ένα καλώδιο console (μπλε rollover, ή USB-to-console) και έναν terminal emulator — PuTTY, screen, ή minicom
  • Βοηθούν έννοιες επιπέδου CCNA — ξέρεις τι είναι μια IP διεύθυνση, ένα VLAN, ένα interface — αλλά δεν χρειάζεται εμπειρία CLI
  • Καμία φοβία μπροστά σε ένα κενό prompt Switch>. Γι' αυτό είναι η ενότητα 01.

01

Πως Μπαινεις — Το Console

Μια ολοκαίνουργια συσκευή Cisco δεν έχει ούτε IP διεύθυνση ούτε SSH. Ο μόνος τρόπος να μπεις είναι η θύρα console — ένα φυσικό καλώδιο και ένας terminal emulator. Αυτό δεν αποτυγχάνει ποτέ, γι' αυτό είναι πάντα το fallback σου.

Το SSH και το Telnet θέλουν IP διεύθυνση και ρυθμίσεις που μια εργοστασιακά καθαρή συσκευή δεν έχει ακόμα. Η θύρα console είναι ο out-of-band τρόπος εισόδου: μια απευθείας σειριακή σύνδεση που δουλεύει πριν ρυθμιστεί ο,τιδήποτε, και εξακολουθεί να δουλεύει όταν έχεις κλειδωθεί έξω μέσω δικτύου. Κάθε σοβαρός τεχνικός Cisco κουβαλάει ένα καλώδιο console στην τσάντα του.

Συνδεσε το Καλωδιο

Βάλε το καλώδιο rollover/USB-console στη θύρα με την ένδειξη CONSOLE πάνω στη συσκευή και στο laptop σου. Στον σύγχρονο εξοπλισμό είναι θύρα console USB-C ή mini-USB· στον παλιότερο είναι το ανοιχτογάλαζο RJ-45 rollover σε έναν USB-serial adapter. Το laptop σου το βλέπει ως σειριακή θύρα (COM).

Το laptop σου — ανοιξε το console (macOS / Linux) 
# Βρες τη σειριακή συσκευή που εμφανίστηκε μόλις τη σύνδεσες
user@laptop:~$ ls /dev/tty.* /dev/ttyUSB*   # macOS: tty.usbserial-XXXX · Linux: ttyUSB0

# Άνοιξέ την στα 9600 baud — το default του console της Cisco
user@laptop:~$ screen /dev/tty.usbserial-A5069RR4 9600
# (παράδειγμα Linux:  screen /dev/ttyUSB0 9600  — ή χρησιμοποίησε minicom)

# Πάτα Enter δυο-τρεις φορές. Θα δεις να εμφανίζεται ένα prompt:
Switch> ▌
# Για να βγεις από το screen αργότερα:  Ctrl+A μετά \  (επιβεβαίωσε με y)

Σε Windows, χρησιμοποίησε PuTTY: διάλεξε Serial, βάλε τη θύρα COM (δες στο Device Manager), και όρισε ταχύτητα 9600. Οι ρυθμίσεις της γραμμής console είναι πάντα ίδιες στον εξοπλισμό Cisco:

ΡυθμισηΤιμη
Speed (baud)9600
Data bits8
ParityNone
Stop bits1
Flow controlNone
⚠ Παγιδα — Μαυρη Οθονη Μετα τη Συνδεση

Ένα μαύρο console που δεν αποκρίνεται είναι σχεδόν πάντα ένα από τρία πράγματα: (1) λάθος baud rate — πρέπει να είναι 9600 (λίγες συσκευές έρχονται στα 115200· δοκίμασέ το αν στα 9600 είναι σιωπηλό)· (2) flow control σε κάτι άλλο από None, που παγώνει την είσοδο· ή (3) λάθος συσκευή COM/tty. Πάτα Enter μερικές φορές — αν η συσκευή κάνει boot θα δεις μηνύματα εκκίνησης, και το prompt εμφανίζεται μόλις τελειώσει. Δεν είναι χαλασμένο· περιμένει.

02

Τα Τρια Modes

Αυτή είναι η μία έννοια που μπερδεύει κάθε αρχάριο. Το IOS έχει ξεχωριστά modes, και το τι επιτρέπεται να πληκτρολογήσεις εξαρτάται εξ ολοκλήρου από το σε ποιο βρίσκεσαι. Διάβασε το prompt — σου λέει πού είσαι.

Η στίξη του prompt δεν είναι διακόσμηση. Ο χαρακτήρας μετά το hostname σου λέει το mode σου, άρα και το επίπεδο δύναμής σου. Μάθε να τον διαβάζεις πριν πληκτρολογήσεις ο,τιδήποτε.

IOS — ανατομια του prompt, απο το λιγοτερο στο πιο ισχυρο 
Switch>
 │     └─ ">"  User EXEC mode — μόνο κοίταγμα. Μια χούφτα αβλαβείς εντολές.
 └─────── hostname (default "Switch" σε switch, "Router" σε router)

Switch#
       └─ "#"  Privileged EXEC — πλήρης πρόσβαση ανάγνωσης: show, copy, reload, debug.

Switch(config)#
             └─ "(config)#"  Global Config — εδώ ΑΛΛΑΖΕΙΣ πράγματα.

Switch(config-if)#
                 └─ ένα sub-mode — ρυθμίζεις τώρα ένα interface.

Μετακινηση Αναμεσα στα Modes

Ανεβαίνεις με enable και configure terminal, και κατεβαίνεις με exit, end, ή Ctrl+Z.

IOS — ανεβαινοντας και κατεβαινοντας τα modes 
# Ξεκίνα στο User EXEC (το ">"). Ανέβα στο Privileged EXEC:
Switch> enable
Switch# ← το "#" σημαίνει ότι τώρα έχεις πλήρη προνόμια

# Μπες στο Global Config για να αλλάξεις τη συσκευή:
Switch# configure terminal
Enter configuration commands, one per line. End with CNTL/Z.
Switch(config)#

# Μπες σε ένα sub-mode (εδώ: ένα interface):
Switch(config)# interface GigabitEthernet0/1
Switch(config-if)#

# το "exit" κατεβαίνει ΕΝΑ επίπεδο:
Switch(config-if)# exit
Switch(config)#

# το "end" (ή Ctrl+Z) πηδά ΤΕΛΕΙΩΣ πίσω στο Privileged EXEC:
Switch(config)# end
Switch#

# το "disable" σε ρίχνει από το Privileged πίσω στο σκέτο User EXEC:
Switch# disable
Switch>
⚠ Παγιδα — Το "Invalid input" Συνηθως Σημαινει Λαθος Mode

Αν το IOS απορρίψει μια εντολή με % Invalid input detected at '^' marker, εννιά στις δέκα είσαι σε λάθος mode — δοκίμασες εντολή show μέσα σε (config)#, ή εντολή config από Switch>. Δες το prompt. Για να τρέξεις μια show χωρίς να βγεις από το config mode, βάλε μπροστά της do (δες το pro tip στην ενότητα 04). Αν αντί γι' αυτό δεις % Incomplete command, το syntax είναι σωστό αλλά σου λείπει ένα όρισμα — πάτα ? για να δεις τι περιμένει.

03

Οι Καλυτεροι σου Φιλοι: ? και Tab

Δεν αποστηθίζεις τις εντολές του IOS. Τις ανακαλύπτεις. Το πλήκτρο "?" σου δείχνει τι είναι διαθέσιμο σε κάθε σημείο, το Tab συμπληρώνει αυτό που ξεκίνησες, και το IOS δέχεται κάθε μονοσήμαντη συντόμευση.

? — Βοηθεια Αναλογα με το Πλαισιο

Πληκτρολόγησε ? οπουδήποτε — μόνο του, μετά από μια λέξη, ή κολλητά σε μια μισοπληκτρολογημένη λέξη — και το IOS σου λέει τι ισχύει σε εκείνο ακριβώς το σημείο.

IOS — το ? σε διαφορετικα σημεια 
# "?" μόνο του — κάθε εντολή διαθέσιμη σε αυτό το mode
Switch# ?
  configure    Enter configuration mode
  copy         Copy from one file to another
  ping         Send echo messages
  reload       Halt and perform a cold restart
  show         Show running system information
  ...

# Μια λέξη + " ?" — τι μπορεί να ακολουθήσει αυτή την εντολή
Switch# show ?
  interfaces   Interface status and configuration
  ip           IP information
  running-config  Current operating configuration
  version      System hardware and software status
  vlan         VLAN information
  ...

# "?" κολλητά σε μισή λέξη — πώς τελειώνει αυτή η εντολή;
Switch# show ver?
version

Tab — Συμπληρωσε το · Συντομευση — Παρ' το Παρακατω

Πάτα Tab για να επεκτείνεις μια μισή λέξη-κλειδί στην πλήρη της μορφή. Ακόμα καλύτερα: δεν χρειάζεται. Το IOS τρέχει οποιαδήποτε συντόμευση είναι μονοσήμαντη — το sh ip int br είναι το ίδιο με το show ip interface brief. Οι έμπειροι operators ζουν με τις συντομεύσεις.

IOS — Tab completion και συντομευση 
# Το Tab επεκτείνει μια μισή λέξη-κλειδί
Switch# conf[Tab]
Switch# configure

# Αυτές οι τέσσερις γραμμές είναι ΟΛΟΙΔΙΕΣ για το IOS — η συντόμευση απλώς δουλεύει:
Switch# show ip interface brief
Switch# sh ip int brief
Switch# sh ip int br
Switch# sho ip in b

# Ο μόνος κανόνας: η συντόμευση πρέπει να είναι μονοσήμαντη. Το "sh c" αποτυγχάνει
# επειδή "clock", "cdp" και άλλα ξεκινούν όλα από c:
Switch# sh c
% Ambiguous command:  "sh c"
💡 Pro Tip — Το ↑ Επαναφερει, και το CLI Δεν σε Κρινει Ποτε

Πάτα ↑ για να γυρίσεις πίσω στις εντολές που έχεις ήδη πληκτρολογήσει — διόρθωσε και ξανατρέξε αντί να πληκτρολογείς ξανά. Συνδύασε τα τρία εργαλεία σαν workflow: γράψε δυο-τρία γράμματα, πάτα ? για να δεις τις επιλογές σου, Tab για να συμπληρώσεις, ↑ για να επαναλάβεις. Δεν χρειάζεται ποτέ να γράψεις ολόκληρη εντολή από μνήμης, και το να διαβάσεις πρώτα το ? σημαίνει ότι καταλαβαίνεις μια εντολή πριν την τρέξεις.

04

Ασφαλεις Show Εντολες Ασφαλες να το Τρεξεις

Ξεκίνα κάθε session από εδώ. Κάθε εντολή "show" είναι read-only — δείχνει κατάσταση και δεν αλλάζει τίποτα. Τρέξ' τες ελεύθερα σε οποιαδήποτε ζωντανή συσκευή για να καταλάβεις τι βλέπεις πριν αγγίξεις ο,τιδήποτε.

Πριν αλλάξεις ο,τιδήποτε, φτιάξε μια εικόνα της συσκευής. Αυτές είναι οι εντολές που θα πληκτρολογείς εκατοντάδες φορές την εβδομάδα. Όλες είναι ασφαλείς σε εξοπλισμό production.

IOS — οι βασικες read-only show εντολες 
# Μοντέλο, έκδοση IOS, uptime, serial number — ξεκίνα πάντα από εδώ
Switch# show version
Cisco IOS Software, C2960X Software, Version 15.2(7)E3
System uptime is 27 weeks, 4 days, 4 hours, 11 minutes
Model number      : WS-C2960X-24TS-L
System serial number : FOC2145X0AB

# Η πιο χρήσιμη εντολή απ' όλες: κάθε interface, το IP του, και το status του
Switch# show ip interface brief
Interface        IP-Address    OK?  Method  Status   Protocol
Vlan1            192.168.1.10  YES  manual  up       up
GigabitEthernet0/1  unassigned  YES  unset   up       up
GigabitEthernet0/2  unassigned  YES  unset   down     down

# Όψη φυσικών θυρών: speed, duplex, και σε ποιο VLAN είναι κάθε access port
Switch# show interfaces status
Port    Name    Status       Vlan   Duplex  Speed Type
Gi0/1           connected    10     a-full  a-1000 10/100/1000BaseTX
Gi0/2           notconnect   1      auto    auto   10/100/1000BaseTX

# VLAN και ποιες θύρες ανήκουν στο καθένα (μόνο switch)
Switch# show vlan brief

# Ο πίνακας MAC — ποια συσκευή μαθαίνεται σε ποια θύρα
Switch# show mac address-table

# Ο πίνακας δρομολόγησης (routers, και switch που κάνουν L3)
Switch# show ip route

# Απευθείας συνδεδεμένοι γείτονες Cisco — ιδανικό για χαρτογράφηση ενός rack
Switch# show cdp neighbors

# Ολόκληρο το running configuration — ό,τι κάνει η συσκευή αυτή τη στιγμή
Switch# show running-config

Φιλτραρισμα Μεγαλου Output

Το show running-config μπορεί να είναι εκατοντάδες γραμμές. Πέρασέ το μέσα από include, section, ή begin για να το κόψεις — το αντίστοιχο του grep.

IOS — το pipe του output (| include / section / begin) 
# Μόνο οι γραμμές που περιέχουν "ip address"
Switch# show running-config | include ip address

# Ολόκληρο το block config για ένα interface
Switch# show running-config | section interface GigabitEthernet0/1

# Ξεκίνα το output από την πρώτη γραμμή που ταιριάζει, μετά δείξε τα υπόλοιπα
Switch# show running-config | begin line vty

# Δουλεύει και σε κάθε show εντολή — π.χ. μόνο τα "up" interfaces
Switch# show ip interface brief | include up
💡 Pro Tip — Τρεξε μια show Χωρις να Βγεις απο το Config Mode

Βαθιά μέσα στο (config-if)# και θέλεις να ελέγξεις κάτι; Δεν χρειάζεται να κάνεις end και να ξαναγυρίσεις. Βάλε μπροστά σε κάθε privileged εντολή το do: το do show ip interface brief την τρέχει εκεί ακριβώς και σε αφήνει ξανά στο ίδιο σημείο. Αυτή η μία λέξη σου γλιτώνει τεράστιο mode-hopping.

05

Το Πρωτο σου Πραγματικο Config Αλλαζει το Config

Τώρα αλλάζουμε πράγματα. Ένα hostname, ένα login banner, και κωδικοί — το ελάχιστο που πρέπει να έχει κάθε συσκευή πριν μπει σε rack. Όλα αυτά γίνονται στο Global Config.

IOS — hostname, διορθωση DNS-lookup, και banner 
Switch# configure terminal
Switch(config)# hostname ACCESS-SW1
ACCESS-SW1(config)# ← το prompt ενημερώνεται ακαριαία

# Σταμάτα το IOS από το να κάνει DNS-resolve τα typo σου (αλλιώς κολλάει 30 δευτ.)
ACCESS-SW1(config)# no ip domain-lookup

# Ένα νομικό banner που εμφανίζεται στο login (οι χαρακτήρες ^ οριοθετούν το κείμενο)
ACCESS-SW1(config)# banner motd ^Authorised access only. Managed device.^
⚠ Παγιδα — enable password vs enable secret

Υπάρχουν δύο εντολές για να προστατέψεις το Privileged EXEC mode. Το enable password αποθηκεύει τον κωδικό σε καθαρό κείμενο (ή εύκολα αναστρέψιμο). Το enable secret αποθηκεύει ένα κανονικό hash. Χρησιμοποίησε πάντα enable secret, και μην ασχοληθείς καθόλου με το enable password — αν είναι ορισμένα και τα δύο, κερδίζει το secret και το password μένει απλώς σαν ευθύνη μέσα στο config σου.

IOS — κωδικοι: enable secret, console, και VTY lines 
# Προστάτεψε το Privileged EXEC με ένα hashed secret
ACCESS-SW1(config)# enable secret S0meStr0ng!Pass

# Κωδικός στη γραμμή console (φυσική πρόσβαση)
ACCESS-SW1(config)# line console 0
ACCESS-SW1(config-line)# password C0ns0le!Pass
ACCESS-SW1(config-line)# login
ACCESS-SW1(config-line)# exec-timeout 10 0   # auto-logout μετά από 10 λεπτά αδράνειας
ACCESS-SW1(config-line)# exit

# Κωδικός στις γραμμές VTY (απομακρυσμένα Telnet/SSH sessions — 0 έως 4 = 5 γραμμές)
ACCESS-SW1(config)# line vty 0 4
ACCESS-SW1(config-line)# password Vty!Pass
ACCESS-SW1(config-line)# login
ACCESS-SW1(config-line)# exit

# Κρυπτογράφησε τους καθαρού-κειμένου κωδικούς μέσα στο config (αδύναμο, αλλά γιατί όχι)
ACCESS-SW1(config)# service password-encryption

06

Ενεργοποιηση SSH — Ο Συγχρονος Τροπος

Το Telnet στέλνει τον κωδικό σου στο καλώδιο σε καθαρό κείμενο. Μην το χρησιμοποιείς ποτέ. Ορίστε η πλήρης συνταγή για να φτάσεις τη συσκευή με ασφάλεια μέσω δικτύου — πέντε υλικά, με τη σειρά.

Το SSH θέλει τέσσερα πράγματα πριν δουλέψει: hostname (έγινε), ένα domain name, RSA crypto keys, και έναν τοπικό λογαριασμό χρήστη. Μετά στρέφεις τις γραμμές VTY μόνο σε SSH και κάνεις login με αυτόν τον λογαριασμό.

IOS — ενεργοποιηση SSH απο το μηδεν 
ACCESS-SW1(config)# # 1. Χρειάζεται domain name για να παραχθούν τα keys
ACCESS-SW1(config)# ip domain-name lab.lan

# 2. Παρήγαγε το RSA key pair. Τα 2048 bits είναι το λογικό ελάχιστο.
ACCESS-SW1(config)# crypto key generate rsa modulus 2048
The name for the keys will be: ACCESS-SW1.lab.lan
% Generating 2048 bit RSA keys, keys will be non-exportable...[OK]

# 3. Ένα τοπικό username με hashed secret (privilege 15 = πλήρης πρόσβαση στο login)
ACCESS-SW1(config)# username admin privilege 15 secret Adm1n!Str0ng

# 4. Επίβαλε SSH v2 και απόρριψε την παλιότερη, πιο αδύναμη v1
ACCESS-SW1(config)# ip ssh version 2

# 5. Στρέψε τις γραμμές VTY μόνο σε SSH, και κάνε authenticate με τους τοπικούς χρήστες
ACCESS-SW1(config)# line vty 0 4
ACCESS-SW1(config-line)# transport input ssh   # μόνο SSH — το Telnet τώρα απορρίπτεται
ACCESS-SW1(config-line)# login local          # χρησιμοποίησε τον λογαριασμό "admin" παραπάνω
ACCESS-SW1(config-line)# end

Χρειάζεσαι επίσης ένα management IP ώστε η συσκευή να είναι προσβάσιμη. Σε ένα switch, αυτό είναι ένα IP σε ένα VLAN interface συν ένα default gateway:

IOS — ενα management IP σε switch (SVI) 
ACCESS-SW1(config)# interface vlan 1
ACCESS-SW1(config-if)# ip address 192.168.1.10 255.255.255.0
ACCESS-SW1(config-if)# no shutdown
ACCESS-SW1(config-if)# exit
ACCESS-SW1(config)# ip default-gateway 192.168.1.1
ACCESS-SW1(config)# end
Το laptop σου — δοκιμασε το login μεσω SSH 
user@laptop:~$ ssh admin@192.168.1.10
Password: 
# δεν εμφανίζεται τίποτα καθώς πληκτρολογείς — φυσιολογικό
ACCESS-SW1# ← μπήκες μέσω SSH, κατευθείαν στο Privileged EXEC (privilege 15)
⚠ Παγιδα — Το SSH Εξακολουθει να Αρνειται τη Συνδεση

Τρεις συνήθεις ύποπτοι: (1) δεν παρήχθησαν keys — το show ip ssh πρέπει να δείχνει SSH enabled και version 2.0· (2) έβαλες login local αλλά δεν έφτιαξες ποτέ username, οπότε δεν υπάρχει λογαριασμός για login — θα κλειδωθείς έξω μέσω δικτύου (μπες από console και διόρθωσέ το)· (3) καμία IP προσβασιμότητα — επιβεβαίωσε ότι το SVI είναι up/up και ότι κάνεις ping τη συσκευή πρώτα. Ακριβώς γι' αυτό κρατάς το καλώδιο console κοντά σου.

07

Αποθηκευση: running-config vs startup-config

Το πιο ακριβό λάθος αρχάριου στον εξοπλισμό Cisco. Οι αλλαγές σου είναι ζωντανές τη στιγμή που τις πληκτρολογείς — αλλά δεν είναι αποθηκευμένες. Μια διακοπή ρεύματος και χάθηκαν όλες. Κατάλαβε αυτά τα δύο αρχεία.

Το IOS κρατάει δύο configurations. Ό,τι μόλις πληκτρολόγησες πήγε στο running-config — το ζωντανό config στη RAM, ενεργό αμέσως. Η συσκευή κάνει boot από το startup-config στη NVRAM. Αν δεν αντιγράψεις το ένα στο άλλο, ένα reboot αναιρεί κάθε αλλαγή που έκανες.

IOS — αποθηκευσε τη δουλεια σου (καν' το συνεχεια) 
# Η πλήρης εντολή — αντίγραψε το running-config στο startup-config
ACCESS-SW1# copy running-config startup-config
Destination filename [startup-config]? ← απλώς πάτα Enter
Building configuration...
[OK]

# Η παλιακή συντόμευση που όλοι πληκτρολογούν στην πράξη — το ίδιο πράγμα:
ACCESS-SW1# write memory
# ή ακόμα πιο σύντομα:  wr

# Δες τι είναι αποθηκευμένο vs τι είναι ζωντανό (αυτό το diff πρέπει να είναι κενό μετά το save)
ACCESS-SW1# show startup-config
ACCESS-SW1# show running-config
⚠ Παγιδα — «Χθες Δουλευε, Τωρα Χαθηκε»

Ρύθμισες ένα switch, το δοκίμασες, όλα δούλευαν — και μετά από βδομάδες ένα τρεμόπαιγμα του ρεύματος το έκανε reboot και το μισό config εξαφανίστηκε. Αυτό είναι ένα μη αποθηκευμένο running-config. Φτιάξε τη συνήθεια: μετά από κάθε αλλαγή που δουλεύει, γράψε wr. Από την άλλη, αυτή η συμπεριφορά είναι ένα δίχτυ ασφαλείας — αν χαλάσεις κάτι άσχημα και δεν έχεις αποθηκεύσει, ένα reload (χωρίς save) σε γυρίζει στο τελευταίο καλό startup-config. Απλώς μην κάνεις ποτέ reload μια συσκευή που δεν φτάνεις φυσικά, χωρίς να είσαι σίγουρος για το τι έχει στο startup.

09

Ενα Πληρες Workflow — Απο την Αρχη ως το Τελος

Όλα τα παραπάνω, με τη σειρά που θα τα έκανες στην πράξη: μπες από console σε ένα εργοστασιακά καθαρό switch και άφησέ το με όνομα, ασφαλισμένο, προσβάσιμο μέσω SSH, και αποθηκευμένο.

IOS — απο το κουτι σε ετοιμο για production 
# Μπες από console, παράλειψε το setup wizard αν σε ρωτήσει (απάντησε "no"), μετά:
Switch> enable
Switch# configure terminal

# Ταυτότητα + ευκολίες
Switch(config)# hostname ACCESS-SW1
ACCESS-SW1(config)# no ip domain-lookup
ACCESS-SW1(config)# banner motd ^Authorised access only.^

# Κωδικοί
ACCESS-SW1(config)# enable secret S0meStr0ng!Pass
ACCESS-SW1(config)# service password-encryption
ACCESS-SW1(config)# line console 0
ACCESS-SW1(config-line)# password C0ns0le!Pass
ACCESS-SW1(config-line)# login
ACCESS-SW1(config-line)# exec-timeout 10 0
ACCESS-SW1(config-line)# exit

# Management IP + gateway
ACCESS-SW1(config)# interface vlan 1
ACCESS-SW1(config-if)# ip address 192.168.1.10 255.255.255.0
ACCESS-SW1(config-if)# no shutdown
ACCESS-SW1(config-if)# exit
ACCESS-SW1(config)# ip default-gateway 192.168.1.1

# SSH
ACCESS-SW1(config)# ip domain-name lab.lan
ACCESS-SW1(config)# crypto key generate rsa modulus 2048
ACCESS-SW1(config)# username admin privilege 15 secret Adm1n!Str0ng
ACCESS-SW1(config)# ip ssh version 2
ACCESS-SW1(config)# line vty 0 4
ACCESS-SW1(config-line)# transport input ssh
ACCESS-SW1(config-line)# login local
ACCESS-SW1(config-line)# end

# Επαλήθευσε, μετά SAVE — το βήμα που ξεχνούν όλοι
ACCESS-SW1# show ip interface brief
ACCESS-SW1# write memory
Building configuration...
[OK]

Συμπερασματα

  1. Διάβασε το prompt πριν πληκτρολογήσεις. Το > είναι μόνο κοίταγμα, το # πλήρης πρόσβαση, το (config)# αλλάζει τη συσκευή. Σχεδόν κάθε "Invalid input" που τρώει ένας αρχάριος είναι στην ουσία λάθος-mode.
  2. Το καλώδιο console είναι το αλεξίπτωτό σου. Δουλεύει πριν υπάρξει κανένα config και αφού έχεις κλειδωθεί έξω μέσω δικτύου. Κράτα ένα στην τσάντα σου· κάθε συνταγή απομακρυσμένης διαχείρισης υποθέτει ότι μπορείς να πέσεις πίσω σ' αυτό.
  3. Το ? και το Tab σημαίνουν ότι δεν αποστηθίζεις ποτέ εντολές. Ανακάλυψέ τες στο prompt. Και συντόμευε ελεύθερα — το sh ip int br είναι υπαρκτό, γρήγορο, και ακριβώς ίσο με την πλήρη εντολή.
  4. Ξεκίνα κάθε session με show. Οι read-only εντολές δεν αλλάζουν τίποτα. Φτιάξε μια εικόνα της συσκευής πριν την αγγίξεις, και χρησιμοποίησε | include / | section για να κόψεις το μεγάλο output.
  5. Χρησιμοποίησε enable secret, ποτέ enable password· χρησιμοποίησε SSH, ποτέ Telnet. Οι ανασφαλείς επιλογές υπάρχουν μόνο για συμβατότητα με τα παλιά. Δεν υπάρχει λόγος να τις διαλέξεις σε ο,τιδήποτε βάζεις σε παραγωγή.
  6. Οι αλλαγές είναι ζωντανές αλλά όχι αποθηκευμένες. Το running-config είναι RAM· το startup-config είναι αυτό που κάνει boot. Μετά από ο,τιδήποτε δουλεύει, γράψε wr. Η μία φορά που θα το παραλείψεις είναι η φορά που μια διακοπή ρεύματος σβήνει ένα απόγευμα δουλειάς.
  7. Το ίδιο CLI τρέχει τα πάντα. Ένα access switch των 200 δολαρίων και ένας core router μιλούν το ίδιο IOS. Η muscle memory που χτίζεις σε αυτή την πρώτη ώρα κλιμακώνεται σε κάθε συσκευή Cisco που θα αγγίξεις ποτέ.

Στηνεις switch Cisco για γραφειο, ξενοδοχειο ή SMB στην Κρητη;

Είτε πρόκειται για ένα access switch είτε για ένα site με πολλά VLAN, το ρυθμίζω και το τεκμηριώνω με τον ίδιο τρόπο — καθαρά, σχολιασμένα configs που η ομάδα σου μπορεί όντως να διαβάσει μετά, όχι ένα μαύρο κουτί που το καταλαβαίνω μόνο εγώ.
