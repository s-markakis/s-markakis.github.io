VRRP First-Hop Redundancy

Κάθε συσκευή στο LAN δείχνει το default gateway της σε έναν router. Κάνε reboot εκείνον τον router και όλο το δίκτυο σβήνει — ακόμα κι αν υπάρχει δεύτερος router δίπλα του, γιατί οι clients δεν ξέρουν ότι υπάρχει. Το VRRP δίνει στους δύο routers ένα κοινό εικονικό gateway ώστε το LAN να μην καταλαβαίνει ποτέ ποιος στην πραγματικότητα κάνει forward. Αυτό είναι το post Cisco HSRP/VRRP σε RouterOS.

MikroTik RouterOS VRRP Redundancy Gateway

Το first-hop redundancy λύνει μια συγκεκριμένη ευθραυστότητα: το default gateway είναι ένα μόνο IP, άρα είναι single point of failure ανεξάρτητα από πόσους routers έχεις. Το VRRP (το ανοιχτό στάνταρ που υλοποιεί και η Cisco, δίπλα στο ιδιόκτητο HSRP της) το διορθώνει με δύο ή περισσότερους routers να μοιράζονται ένα εικονικό IP και εικονικό MAC. Ο ένας είναι master και κάνει forward· οι άλλοι είναι backup και μένουν σιωπηλοί μέχρι ο master να σταματήσει να στέλνει διαφημίσεις VRRP, οπότε ο backup με την υψηλότερη priority αναλαμβάνει το εικονικό IP σε περίπου ένα δευτερόλεπτο. Οι clients κρατάνε την ίδια διεύθυνση gateway σε όλη τη διάρκεια και ποτέ δεν ξανακάνουν ARP.

Στο RouterOS ένα instance VRRP είναι ένα εικονικό interface στο οποίο προσαρτάς την κοινή διεύθυνση. Οι μηχανισμοί καθρεφτίζουν το Cisco IOS: First-Hop Redundancy — η priority εκλέγει τον master, το preemption αποφασίζει αν ένας ανακτημένος router ξαναπαίρνει τον έλεγχο, και το ενδιαφέρον engineering είναι να κάνεις το failover να πυροδοτείται σε νεκρό uplink, όχι μόνο σε νεκρό router.

Προαπαιτουμενα
  • Δύο boxes RouterOS στο ίδιο segment LAN, το καθένα με τη δική του πραγματική διεύθυνση
  • Μια ελεύθερη διεύθυνση για το εικονικό gateway (π.χ. .1, με τους routers στα .2/.3)

01

Οι Δυο Routers

Ίδιο VRID, ίδιο εικονικό IP, διαφορετικές priorities. Η υψηλότερη priority είναι master. Το εικονικό IP μπαίνει στο interface VRRP, όχι στο φυσικό.

Router A (MASTER · πραγματικο .2) — instance VRRP + εικονικο gateway 
# Το instance VRRP κάθεται πάνω στο bridge του LAN· υψηλότερη priority = master.
> /interface vrrp add name=vrrp-lan interface=bridge vrid=10 priority=200 version=3
# Η ΚΟΙΝΗ διεύθυνση gateway ζει στο interface vrrp.
> /ip address add address=10.10.0.1/24 interface=vrrp-lan
# Η δική του διεύθυνση management του Router A μένει στο ίδιο το bridge:
> /ip address add address=10.10.0.2/24 interface=bridge
Router B (BACKUP · πραγματικο .3) — πανομοιοτυπο, χαμηλοτερη priority 
> /interface vrrp add name=vrrp-lan interface=bridge vrid=10 priority=100 version=3
> /ip address add address=10.10.0.1/24 interface=vrrp-lan   # ΙΔΙΟ VIP
> /ip address add address=10.10.0.3/24 interface=bridge
# Οι clients βάζουν το gateway τους στο 10.10.0.1 και ποτέ δεν νοιάζονται ποιος router το κατέχει.
⚠ Παγιδα — Ιδιο VRID στο Segment, και Μονο Ενας Κατοχος VIP

Και οι δύο routers πρέπει να μοιράζονται το ίδιο vrid — έτσι αναγνωρίζουν τις διαφημίσεις ο ένας του άλλου και παράγουν το πανομοιότυπο εικονικό MAC (00:00:5E:00:01:0A για VRID 10). VRID που δεν ταιριάζουν σημαίνει δύο routers που νομίζουν και οι δύο ότι είναι master, απαντώντας και οι δύο για το .1 — ένας εφιάλτης διπλού IP. Επίσης βάλε την κοινή διεύθυνση μόνο στο interface vrrp-lan· αν κατά λάθος προσθέσεις το .1 και στο φυσικό bridge, έχεις ακυρώσει όλο τον μηχανισμό.

02

Preemption & Επαληθευση Mastership Ασφαλες να το Τρεξεις

Πρέπει ένας ανακτημένος master να ξαναπάρει την κορόνα, ή να την αφήσει στον backup; Αυτό είναι το preemption. Μετά επιβεβαίωσε ποιος είναι πραγματικά master και τέσταρε ένα πραγματικό failover.

Terminal — παρακολουθησε state, ελεγξε preemption 
> /interface vrrp monitor vrrp-lan
     state: master
  master-adv...: 00:00:00

# Το preemption είναι on by default: ένας router με υψηλότερη priority που επιστρέφει
# ξαναπαίρνει τον ρόλο master. Απενεργοποίησέ το για να αποφύγεις ένα δεύτερο τίναγμα στην ανάκτηση:
> /interface vrrp set vrrp-lan preemption-mode=no
# Τεστ: απενεργοποίησε vrrp στο A και δες το B να γίνεται master μέσα σε ~1s.

03

Κανε Failover σε Νεκρο WAN, Οχι Μονο Νεκρο Router

Το απλό VRRP αντιδρά μόνο όταν ο master σταματά να διαφημίζει — δηλαδή όταν πεθαίνει ο ίδιος ο router. Αλλά αν ο master είναι ζωντανός με νεκρό uplink, κρατά ευχαρίστως τον ρόλο master και ρίχνει το LAN σε blackhole. Πρέπει να τον διδάξεις να υποβιβάζεται μόνος του.

Terminal — το netwatch ριχνει την priority VRRP οταν το gateway WAN γινεται απροσιτο 
# Κάνε probe έναν off-net στόχο μέσω του WAN· σε αστοχία, κατέβασε τη δική μας priority VRRP
# κάτω από τον backup ώστε το B να αναλάβει. Επανάφερέ την στην ανάκτηση.
> /tool netwatch add host=1.1.1.1 interval=5s \
    down-script="/interface vrrp set vrrp-lan priority=50" \
    up-script="/interface vrrp set vrrp-lan priority=200"
# Τώρα μια αστοχία ζωντανός-router/νεκρό-WAN υποβιβάζει τον master και το LAN
# ακολουθεί το uplink που δουλεύει. Ταιριάζει με failover routing dual-WAN.
💡 Pro Tip — Κρατα τα Configs των Δυο Routers σε Απολυτο Συγχρονισμο

Το VRRP προστατεύει το gateway, αλλά ο backup είναι χρήσιμος μόνο αν μπορεί πραγματικά να κάνει route ό,τι έκανε ο master — ίδιο NAT, ίδιο firewall, ίδια static routes, ίδιες επιλογές DHCP. Το κλασικό outage είναι ένα failover σε έναν backup που ποτέ δεν κρατήθηκε ενημερωμένος. Αντιμετώπισε το ζευγάρι ως μία μονάδα: άλλαξε και τα δύο μαζί, και σκέψου να τα οδηγείς και τα δύο από το ίδιο template στο διαχειριση fleet. Αυτή είναι ακριβώς η πειθαρχία στην οποία στηρίχθηκε το field build ξενοδοχείου.

Βασικα Συμπερασματα

  1. Το default gateway ειναι single point of failure μέχρι δύο routers να το μοιραστούν. Το VRRP δίνει στο LAN ένα εικονικό IP/MAC που επιβιώνει τον θάνατο ενός router.
  2. Ίδιο VRID, ίδιο VIP, διαφορετική priority — η υψηλότερη priority είναι master. Βάλε την κοινή διεύθυνση μόνο στο interface VRRP.
  3. Το failover είναι κάτω από ένα δευτερόλεπτο και αόρατο στους clients — κρατάνε το ίδιο gateway και ποτέ δεν ξανακάνουν ARP.
  4. Το preemption είναι επιλογή: ξαναπάρε τον ρόλο master για προβλεψιμότητα, ή άφησέ το για ένα λιγότερο τίναγμα στην ανάκτηση.
  5. Το απλό VRRP αγνοεί νεκρό uplink. Χρησιμοποίησε netwatch για να ρίξεις την priority όταν αποτυγχάνει το WAN ώστε ένα box ζωντανός-router/νεκρό-WAN να υποβιβάζεται μόνο του.
  6. Κράτα τα configs και των δύο routers πανομοιότυπα. Ένας backup που δεν μπορεί να κάνει route ό,τι έκανε ο master είναι ψεύτικη αίσθηση ασφάλειας.

Ενας router αναμεσα στην επιχειρηση σου και μια χαμενη μερα κρατησεων;

Χτίζω redundant gateways σε MikroTik και Cisco με ζευγάρια VRRP, σωστό tracking uplink, και configs που πραγματικά ταιριάζουν και στις δύο πλευρές — ώστε ένας νεκρός router ή μια νεκρή γραμμή να είναι non-event αντί για τηλεφώνημα.
