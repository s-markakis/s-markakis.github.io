Κεντρικο Wi-Fi
με CAPsMAN

Δέκα access points σε έναν διάδρομο ξενοδοχείου, ένα config. Το CAPsMAN γυρνά μια στοίβα APs MikroTik σε ένα ενιαίο διαχειριζόμενο σύστημα — άλλαξε το password επισκεπτών μία φορά και κάθε radio ενημερώνεται, πρόσθεσε ένα AP και κληρονομεί τα πάντα, και οι επισκέπτες κάνουν roam από δωμάτιο σε δωμάτιο χωρίς να κόβονται. Αυτός είναι ο τρόπος του RouterOS 7 (WifiWave2), και η φυσική συνέχεια του lab ξενοδοχείου.

RouterOS 7 CAPsMAN WifiWave2 Wireless Roaming Φιλοξενια cAP

Το lab ξενοδοχείου έκανε config δύο APs με το χέρι, το καθένα με τα δικά του SSIDs. Αυτό είναι εντάξει για δύο. Για δέκα — έναν διάδρομο δωματίων, ένα λόμπι, ένα pool bar — το να κάνεις config το καθένα με το χέρι είναι το πώς καταλήγεις με ένα AP σε λάθος VLAN, ένα άλλο να διαφημίζει ακόμα το password της περασμένης σεζόν, και επισκέπτες των οποίων η σύνδεση κόβεται κάθε φορά που περνάνε δίπλα από τα ασανσέρ. Το CAPsMAN (Controlled Access Point system MANager) το διορθώνει: ένας router γίνεται ο manager, τα APs γίνονται CAPs (Controlled APs) που κατεβάζουν όλο το config τους από αυτόν. Άλλαξε κάτι μία φορά· κάθε AP ακολουθεί.

Το RouterOS 7 ξανάχτισε το wireless γύρω από τον driver WifiWave2, και το CAPsMAN μαζί του — το config ζει κάτω από το /interface/wifi, όχι το παλιό /caps-man. Αυτό το post χρησιμοποιεί το μοντέρνο stack: έναν manager, μια κοινή διαμόρφωση που μοιράζονται όλα τα radios, SSIDs με VLAN tags που ρίχνουν τους επισκέπτες κατευθείαν στο απομονωμένο δίκτυο επισκεπτών, μη επικαλυπτόμενα κανάλια, και το roaming που κάνει το «περπάτα οπουδήποτε» να δουλεύει. Είναι το επιστέγασμα που κάνει το lab ξενοδοχείου να κλιμακώνει.

Προαπαιτουμενα
  • Το lab Δικτύου Ξενοδοχείου — αυτό κλιμακώνει τα δύο χειροχτισμένα APs του σε διαχειριζόμενο fleet
  • VLAN Segmentation — το CAPsMAN ρίχνει κάθε SSID σε ένα VLAN μέσω του trunk
  • RouterOS 7.13+ στον manager και στα APs· APs MikroTik με driver wifi-qcom/wifi-qcom-ac (cAP ax, hAP ax, κλπ.)

01

Ενεργοποιησε τον Manager

Οποιαδήποτε συσκευή RouterOS 7 μπορεί να είναι ο manager — συνήθως το gateway. Μία γραμμή τον ανάβει· τα CAPs θα τον βρουν μέσω του τοπικού δικτύου.

RouterOS 7 — στο gateway (ο manager) 
[admin@GW] > /interface/wifi/capsman set enabled=yes \
    interfaces=vlan99-mgmt package-path="" upgrade-policy=suggest-same-version

# Δες τα CAPs να προσπαθούν να μπουν (μόλις δείξουν εδώ — section 02):
[admin@GW] > /interface/wifi/capsman remote-cap print
 #  ADDRESS           IDENTITY     STATE    COMMON-NAME
 0  10.10.99.21       cap-lobby    Run      D4:01:...:21
 1  10.10.99.22       cap-wingA    Run      D4:01:...:22
💡 Κανε Διαχειριση στο VLAN Management

Δείξε το interfaces= του CAPsMAN στο VLAN management, όχι στο guest. Το κανάλι ελέγχου CAPWAP ανάμεσα σε manager και CAPs (discovery, config push, keys) πρέπει να πατάει στο ίδιο απομονωμένο segment management με ό,τι άλλο διαχειρίζεσαι — ποτέ στο δίκτυο όπου είναι οι επισκέπτες. Αυτή είναι η ασύρματη μισή της πειθαρχίας segmentation από το lab ξενοδοχείου: control plane στο VLAN 99, κίνηση επισκεπτών tunnelled/tagged ξεχωριστά.

02

Γυρνα ενα AP σε CAP

Σε κάθε access point, μία εντολή δίνει τα radios του στον manager και σταματά να είναι standalone συσκευή. Μετά από αυτό, δεν ξανακάνεις ποτέ login στο AP — το διαχειρίζεσαι από τον manager.

RouterOS 7 — σε καθε access point 
# Κάνε reset σε καθαρό CAP: δώσε και τα δύο radios στο CAPsMAN, βρες τον manager
# στο τοπικό segment, και υιοθέτησε το config του.
[admin@cap-lobby] > /interface/wifi/cap set enabled=yes \
    discovery-interfaces=vlan99-mgmt slaves-datapath=bridge1 \
    caps-man-addresses=10.10.99.1

# Το ίδιο το bridge του AP χρειάζεται απλώς το VLAN management για έλεγχο + τα
# VLAN guest/staff tagged στο uplink του ώστε το CAPsMAN να τοποθετήσει SSIDs πάνω τους.
⚠ Παγιδα — «Το CAP δεν Μπαινει» Ειναι Σχεδον Παντα Discovery η Version

Δύο τρόποι αστοχίας καλύπτουν το 90% των κολλημένων CAPs. Πρώτο, το discovery: ο manager και το CAP πρέπει να μοιράζονται ένα segment Layer-2 (το VLAN management) για auto-discovery, ή πρέπει να βάλεις caps-man-addresses= ρητά (όπως παραπάνω) ώστε το CAP να κάνει unicast σε έναν manager πέρα από ένα σύνορο L3. Δεύτερο, driver/version: το CAPsMAN του WifiWave2 απαιτεί ο manager και κάθε CAP να είναι σε συμβατές εκδόσεις RouterOS 7 με τον driver wifi-qcom — ένα AP ακόμα σε παλιό package ή μια συσκευή v6 απλά δεν θα εμφανιστεί. Έλεγξε /interface/wifi/capsman remote-cap print — αν ένα CAP δεν εμφανίζεται καν, είναι discovery· αν εμφανίζεται αλλά κολλάει, είναι version/driver.

03

Ενα Config, Καθε Radio

Όλο το νόημα: όρισε τα SSIDs, security, και VLAN mapping μία φορά ως ονομασμένα configurations, μετά κάνε τους provisioning σε κάθε CAP αυτόματα. Άλλαξε το config, κάθε AP το ξανακληρονομεί.

RouterOS 7 — configurations + provisioning στον manager 
# Προφίλ security (τα passwords), ορισμένα μία φορά
[admin@GW] > /interface/wifi/security add name=sec-guest authentication-types=wpa2-psk,wpa3-psk passphrase="summer-in-crete"
[admin@GW] > /interface/wifi/security add name=sec-staff authentication-types=wpa2-psk,wpa3-psk passphrase="********"

# Datapath: σε ποιο VLAN πέφτει κάθε SSID, bridged πίσω στο gateway
[admin@GW] > /interface/wifi/datapath add name=dp-guest bridge=bridge1 vlan-id=20
[admin@GW] > /interface/wifi/datapath add name=dp-staff bridge=bridge1 vlan-id=10

# Ονομασμένα configurations = SSID + security + datapath + πλάνο καναλιού
[admin@GW] > /interface/wifi/configuration add name=cfg-guest ssid="Hotel-Guest" security=sec-guest datapath=dp-guest
[admin@GW] > /interface/wifi/configuration add name=cfg-staff ssid="Hotel-Staff" security=sec-staff datapath=dp-staff

# Κανόνας provision: κάθε CAP που μπαίνει παίρνει και τα ΔΥΟ SSIDs, auto κανάλι
[admin@GW] > /interface/wifi/provisioning add action=create-dynamic-enabled \
    supported-bands=2ghz-ax,5ghz-ax master-configuration=cfg-guest slave-configurations=cfg-staff
💡 Αλλαξε Μια Φορα, Παντου — Ολος ο Λογος να το Κανεις

Αλλάζει η σεζόν και ο ιδιοκτήτης θέλει νέο password επισκεπτών; /interface/wifi/security set sec-guest passphrase="autumn-in-crete" — μία γραμμή, και κάθε CAP στο κτίριο ενημερώνεται στο επόμενο config push. Νέο AP για την επεκταμένη βεράντα; Βάλ' το στην πρίζα, τρέξε τη μία γραμμή cap set από το section 02, και κληρονομεί και τα δύο SSIDs, το VLAN mapping, και το πλάνο καναλιού χωρίς κανένα επιπλέον config. Αυτό το «μία αλλαγή, παντού» είναι όλη η απόδοση του CAPsMAN, και είναι αυτό που κάνει ένα ακίνητο με δέκα APs συντηρήσιμο από έναν άνθρωπο.

04

Καναλια & Roaming

Δύο πράγματα ξεχωρίζουν το «αρκετά APs» από «ένα δίκτυο Wi-Fi που ο επισκέπτης δεν σκέφτεται ποτέ»: μη επικαλυπτόμενα κανάλια ώστε τα APs να μη μαλώνουν, και γρήγορο roaming ώστε το περπάτημα ανάμεσά τους να μην κόβει την κλήση.

RouterOS 7 — πλανο καναλιου + roaming 
# Άφησε το CAPsMAN να διαλέξει μη επικαλυπτόμενα κανάλια, ή κάρφωσέ τα ανά-CAP.
# Το 2.4GHz έχει μόνο τρία που δεν επικαλύπτονται: 1, 6, 11 — εναλλάσσοντάς τα.
[admin@GW] > /interface/wifi/channel add name=ch-2g-auto band=2ghz-ax skip-dfs-channels=all
[admin@GW] > /interface/wifi/channel add name=ch-5g-auto band=5ghz-ax

# Ενεργοποίησε 802.11k/v/r στο configuration ώστε οι clients να κάνουν roam καθαρά —
# αναφορές γειτόνων (k), BSS transition (v), γρήγορο transition (r).
[admin@GW] > /interface/wifi/configuration set cfg-guest \
    .steering.rrm=yes .steering.wnm.bss-transition=yes

# Επαλήθευσε τι επέλεξε πραγματικά κάθε CAP και ποιος είναι συνδεδεμένος πού:
[admin@GW] > /interface/wifi/radio print
[admin@GW] > /interface/wifi/registration-table print
⚠ Παγιδα — Το Ιδιο SSID Κανει το Roaming να Δουλευει· το Ιδιο Καναλι το Χαλαει

Για να κάνει ένας επισκέπτης roam απρόσκοπτα, κάθε CAP πρέπει να διαφημίζει το πανομοιότυπο SSID και password — που το εγγυάται το CAPsMAN, αφού μοιράζονται ένα configuration. Αλλά η ανάποδη πλευρά πιάνει τον κόσμο: APs σε επικαλυπτόμενα κανάλια (δύο γείτονες και οι δύο στο κανάλι 1 του 2.4GHz, ή χειρότερα κανάλια 1 και 3) παρεμβάλλονται μεταξύ τους και ρίχνουν το throughput για όλους στην εμβέλεια. Η διόρθωση είναι ένα πλάνο καναλιού — 1/6/11 στο 2.4GHz, απλωμένα τα πλατιά κανάλια 5GHz — είτε auto-επιλεγμένα είτε καρφωμένα ανά CAP με βάση τη φυσική τοποθεσία. Ίδιο όνομα, διαφορετικό κανάλι: αυτή είναι η συνταγή.

05

Λειτουργια & Παρακολουθηση Ασφαλες να το Τρεξεις

Μόλις τρέχει, ο manager είναι το single pane of glass σου — κάθε AP, κάθε client, κάθε κανάλι, από ένα CLI. Αυτές είναι οι εντολές στις οποίες θα ζεις στην πράξη.

ΕντοληΤι δειχνει
/interface/wifi/capsman remote-cap printΚάθε CAP, το state του (Run = υγιές), διεύθυνση, και identity.
/interface/wifi/registration-table printΚάθε συνδεδεμένος client — ποιο AP, σήμα, ρυθμός. Το εργαλείο «γιατί είναι αργό το δωμάτιο 12».
/interface/wifi/radio printΤο επιλεγμένο κανάλι και band κάθε radio — εντόπισε δύο γείτονες να συγκρούονται.
/interface/wifi printΤα provisioned virtual APs σε κάθε CAP (guest + staff ανά radio).
/log print where topics~"caps"Events join/leave — ένα CAP που συνεχώς ξαναμπαίνει είναι πρόβλημα PoE ή uplink.
/interface/wifi/capsman remote-cap upgradeΣτείλε ταιριαστή έκδοση RouterOS σε κάθε CAP ταυτόχρονα.
💡 Ενα CAP που Φλαπαρει Σχεδον Ποτε Δεν Ειναι Wi-Fi

Όταν ένα CAP επανειλημμένα πέφτει και ξαναμπαίνει στο log, αντιστάσου στο να κάνεις debug το wireless — είναι σχεδόν πάντα φυσικό: ένας οριακός PoE injector, μια μακριά ή κατεστραμμένη διαδρομή προς εκείνο το AP, ή ένα switch port που ξαναδιαπραγματεύεται. Ο πίνακας registration και τα στατιστικά radio θα φαίνονται μια χαρά μέχρι να εξαφανιστεί το CAP. Έλεγξε πρώτα το switch port και το budget PoE για εκείνη τη διαδρομή· έχουμε ξοδέψει ώρες «ρυθμίζοντας το roaming» σε κάτι που αποδείχτηκε ένα σπασμένο καλώδιο πίσω από ένα κεφαλάρι.

06

MikroTik ↔ Cisco — Κεντρικο Wireless

Το CAPsMAN είναι η απάντηση του MikroTik στο wireless LAN controller — ίδια ιδέα, ένα κλάσμα της τιμής και του licensing.

MikroTik / RouterOS 7Cisco
CAPsMAN managerWireless LAN Controller (WLC) / Catalyst 9800
CAP (Controlled AP)Lightweight AP joined στο WLC (CAPWAP)
/interface/wifi/configurationWLAN profile + policy/RF tag
datapath vlan-id ανα SSIDWLAN → VLAN mapping / policy profile
κανόνας provisioningAP join profile + tags
steering (k/v/r)802.11k/v/r κάτω από το RF/policy profile
Δωρεάν — καμία licence ανά-APDNA/Smart licensing ανά AP

Βασικα Συμπερασματα

  1. Το CAPsMAN κάνει πολλά APs να συμπεριφέρονται σαν ένα σύστημα — ο manager κρατά το config, τα CAPs το κατεβάζουν. Άλλαξε μία φορά, κάθε AP ακολουθεί· πρόσθεσε ένα AP, κληρονομεί τα πάντα.
  2. Χρησιμοποίησε το stack WifiWave2 του RouterOS 7 (/interface/wifi/...) σε 7.13+ με τον driver wifi-qcom — όχι το legacy /caps-man.
  3. Τρέξε το control plane στο VLAN management, και βάλε tag τα SSIDs guest/staff στα δικά τους VLAN μέσω του datapath — η ασύρματη μισή του segmentation.
  4. Όρισε SSID + security + datapath μία φορά ως configurations, μετά ένας κανόνας provisioning τα στέλνει σε κάθε CAP αυτόματα.
  5. Το ίδιο SSID παντού ενεργοποιεί roaming· ένα πλάνο καναλιού αποτρέπει αυτο-παρεμβολή. 1/6/11 στο 2.4GHz, και ενεργοποίησε steering 802.11k/v/r.
  6. Ο manager είναι ένα pane of glass — το remote-cap και το registration-table απαντούν «είναι όλα τα APs up» και «γιατί είναι αργό εκείνο το δωμάτιο» από ένα CLI.
  7. Ένα CAP που φλαπάρει είναι φυσικό — PoE, καλωδίωση, το switch port — πολύ πριν να είναι ρύθμιση wireless.

Ενα ακινητο οπου το Wi-Fi κοβεται καθως περπατανε οι επισκεπτες;

Μόλις ένα ακίνητο έχει περισσότερα από δύο-τρία access points, η διαχείρισή τους ένα-ένα σταματά να κλιμακώνει. Σχεδιάζω wireless διαχειριζόμενο με CAPsMAN με ένα config, απρόσκοπτο roaming, κίνηση επισκεπτών σωστά απομονωμένη, και ένα πλάνο καναλιού που δεν μαλώνει με τον εαυτό του.
