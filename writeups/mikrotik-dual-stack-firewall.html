Dual-Stack Parity:
The IPv6 Holes

A typical case: the IPv4 firewall is textbook, with default deny on input and forward, management only from the admin VLAN and a tidy port forward for the NAS. Scan the same router over IPv6 and Winbox, the DNS resolver and the NAS's admin page answer from the internet. Nothing on the IPv4 side is wrong. The IPv6 side has no rules at all.

RouterOS IPv6 Firewall Dual Stack Starlink DHCPv6-PD Auditing

RouterOS keeps two firewalls, one per address family, and they share nothing except interface lists and the connection tracker. A router can be default-deny over IPv4 and accept-all over IPv6 at the same time, and on a Starlink or fibre link with a delegated prefix the second one is reachable from anywhere.

This post is about that gap, not about ICMPv6 itself; the full RFC 4890 treatment is in IPv6 in Depth: the firewall, done right. Here: how to spot the gap, the parity ruleset, port forwards without NAT, and Starlink.

Prerequisites
  • The RouterOS firewall, properly
  • MikroTik IPv6 fundamentals
  • A host with IPv6 outside your network to test from

01

How It Happens

Nobody decides to leave IPv6 open. It happens because two separate firewalls exist and only one of them was written.

On RouterOS 7, IPv6 is part of the main package and enabled by default. Its firewall lives in /ipv6 firewall, entirely separate from /ip firewall: separate filter, separate RAW, separate address lists. The default configuration includes a sensible IPv6 ruleset, which is exactly why the problem is so common: installers who start with /system reset-configuration no-defaults=yes and build their own IPv4 firewall end up with a full IPv4 policy and an empty IPv6 one.

For years that didn't matter, because many ISPs delivered no IPv6 at all. Then two things changed: fibre ISPs started handing out prefixes, and Starlink delegates a /56 to every terminal. The day the WAN gets a prefix, every LAN host gets a global address, and the empty IPv6 filter accepts everything in both directions.

⚠ Gotcha — CGNAT felt like a firewall. IPv6 has no CGNAT.

Behind Starlink or most 4G, the router's IPv4 WAN address is in 100.64.0.0/10. Nothing on the internet can start a connection to it, so a missing IPv4 input rule never shows. That habit carries over badly: on the same link, IPv6 is a routable /56 with no NAT anywhere, and the NAS, the cameras and the router's own Winbox are directly addressable.

02

The 60-Second Audit

Five read-only commands tell you whether a router is exposed over IPv6 right now.

RouterOS — is IPv6 live, and is it filtered? Safe to Run 
/ipv6 settings print
# disable-ipv6: no   forward: yes   accept-router-advertisements: yes-if-forwarding-disabled
/ipv6 address print where global
# a 2a0d:... or 2001:... address on the WAN or the bridge = IPv6 is live
/ipv6 route print where dst-address=::/0
/ipv6 firewall filter print count-only
# 0 = everything accepted, in and through
/ip dns print
# allow-remote-requests: yes = a resolver that also answers on every IPv6 address
From outside — prove it, don't assume it Safe to Run 
# from a host with IPv6 (a VPS, a phone hotspot with IPv6):
nmap -6 -Pn -p 22,53,80,443,8291,8728,8729 2a0d:xxxx:xxxx:xx00::1
# do NOT sweep a /64: find the LAN hosts from the router's neighbour table instead
/ipv6 neighbor print where status=reachable
⚠ Gotcha — You can't scan your way to every host

A /64 has 264 addresses, so the "nobody will find it" argument sounds convincing. It isn't: addresses leak through DNS, TLS certificate logs, outbound connections and EUI-64 suffixes derived from MACs. The router's neighbour table is how you find what is actually there; the filter is what protects it.

03

The Parity Ruleset

Mirror the intent of the IPv4 firewall, not its text. What changes is ICMPv6, DHCPv6 and the absence of NAT.

RouterOS — an IPv6 filter that matches a default-deny IPv4 one 
/ipv6 firewall address-list
add list=bad_ipv6 address=::/128 comment="unspecified"
add list=bad_ipv6 address=::1/128 comment="loopback"
add list=bad_ipv6 address=fec0::/10 comment="site-local, deprecated"
add list=bad_ipv6 address=::ffff:0.0.0.0/96 comment="IPv4-mapped"
add list=bad_ipv6 address=2001:db8::/32 comment="documentation"
add list=bad_ipv6 address=100::/64 comment="discard-only"
/ipv6 firewall filter
add chain=input connection-state=established,related,untracked action=accept
add chain=input connection-state=invalid action=drop
add chain=input protocol=icmpv6 action=accept comment="ND, RA, PMTU: see the RFC 4890 post"
add chain=input protocol=udp dst-port=33434-33534 action=accept comment="traceroute"
add chain=input protocol=udp src-address=fe80::/10 dst-port=546 action=accept \
    comment="DHCPv6 replies: the prefix from the ISP"
add chain=input in-interface-list=LAN action=accept
add chain=input action=drop comment="FINAL DROP input v6"
add chain=forward connection-state=established,related,untracked action=accept
add chain=forward connection-state=invalid action=drop
add chain=forward src-address-list=bad_ipv6 action=drop
add chain=forward dst-address-list=bad_ipv6 action=drop
add chain=forward protocol=icmpv6 hop-limit=equal:1 action=drop \
    comment="RFC 4890: never forward hop-limit 1"
add chain=forward protocol=icmpv6 action=accept
add chain=forward in-interface-list=LAN out-interface-list=WAN action=accept
add chain=forward action=drop comment="FINAL DROP forward v6"
IPv4 ruleIPv6 counterpartNote
accept established, related, untrackedidenticalSame tracker, separate table.
accept ICMP (limited)accept ICMPv6, drop hop-limit 1 in forwardIPv6 breaks without ND and Packet Too Big. Details in the RFC 4890 post.
DHCP client on the WAN (udp 68)udp 546 from fe80::/10Without it the prefix never arrives, or stops renewing.

💡 Write both rules in the same change

The cheapest control is procedural: no IPv4 filter change is complete until its IPv6 counterpart is in the same commit, with the same comment. A "management from these networks" rule that exists only in /ip is half a rule.

04

Port Forwards Without NAT

In IPv4 the port forward was the only way in. In IPv6 every host is already "forwarded", and the filter is the only thing that says no.

RouterOS — publish one service, not the whole host 
# IPv4: dst-nat 203.0.113.10:443 -> 192.168.88.10:443, plus the filter rule
#   chain=forward connection-nat-state=dstnat action=accept
# IPv6: no translation; allow exactly the service on exactly the host
/ipv6 firewall address-list
add list=published-web address=2a0d:xxxx:xxxx:xx10::10/128 comment="NAS web"
/ipv6 firewall filter
add chain=forward in-interface-list=WAN dst-address-list=published-web \
    protocol=tcp dst-port=443 action=accept \
    place-before=[find comment="FINAL DROP forward v6"]
⚠ Gotcha — Delegated prefixes change

If the ISP's prefix changes, so does every global address, and an address-list entry with the old prefix silently stops matching. Ask for a static prefix where you publish services, or keep the published hosts on a fixed interface ID and update the list from a script on the DHCPv6 client's prefix change. Starlink prefixes do change.

Note the absence of a rule for the reverse direction: established replies are already accepted at the top of the chain. Everything the old NAT did "for free", blocking unsolicited inbound connections, is now the job of the final drop in forward.

05

Starlink, Done Properly

The terminal in bypass mode gives the router an IPv6 default route by RA and a /56 by DHCPv6-PD. Take both, deliberately.

RouterOS — IPv6 behind a Starlink in bypass mode 
# a forwarding router ignores RAs unless told otherwise
/ipv6 settings set accept-router-advertisements=yes
/ipv6 dhcp-client add interface=ether1 request=prefix pool-name=starlink6 \
    pool-prefix-length=64 add-default-route=no use-peer-dns=no
# one /64 from the delegated /56 for the LAN bridge, advertised to clients
/ipv6 address add interface=bridge from-pool=starlink6 address=::1 advertise=yes
# the parity ruleset from section 3 goes in BEFORE this point
⚠ Gotcha — Order of operations

Apply the IPv6 filter first, then add the DHCPv6 client. If the prefix arrives first, there is a window, minutes or months, in which every LAN host has a global address and no filter. On a router you are converting, run the 60-second audit, install the ruleset in Safe Mode, then enable or verify the WAN side.

06

The Cisco Side

IOS has the opposite default, and the same lesson.

TopicRouterOSIOS / IOS-XE
IPv6 routing by defaultonoff until ipv6 unicast-routing
Firewall per familyseparate /ipv6 firewallACLs separate (ipv6 traffic-filter); zone-based firewall inspects both if the class-maps match IPv6
Address lists / object-groupsper familyobject-group network per family
First-hop protectionbridge filters, RA guard on switch chipsRA Guard, DHCPv6 Guard, IPv6 Source Guard

On IOS, turning on ipv6 unicast-routing without IPv6 ACLs or zone membership produces the same hole. Zone-based firewall helps: an interface in a zone is filtered for both families, as long as the inspect class-maps don't match only IPv4 ACLs.

07

Verify It

The test is the one an attacker would run: from outside, over IPv6.

TestExpected
nmap -6 the router's WAN and LAN addresses from outsideEverything filtered; ICMPv6 echo may answer.
nmap -6 a LAN host's global address from outsideFiltered, except the published service.
LAN client: curl -6 https://ifconfig.coWorks: outbound IPv6 is allowed.
/ipv6 firewall filter print stats after the scansThe final drops counted your probes.
Renew the prefix (or reboot the Starlink)Prefix returns, the filter still applies, published service list updated.

Takeaways

  1. Two families, two firewalls. /ip firewall rules do nothing for IPv6; only interface lists and the tracker are shared.
  2. No-defaults resets remove the IPv6 ruleset that the default configuration would have given you.
  3. CGNAT is not a firewall, and IPv6 has none. On Starlink the IPv6 side is globally routable from day one.
  4. Mirror intent, not text: ICMPv6 and DHCPv6 need their own accepts; address lists need IPv6 twins.
  5. Without NAT, the final forward drop does what NAT used to. Publish services by host and port, and watch for prefix changes.
  6. Filter first, prefix second. Never let the WAN hand out a prefix to a router without an IPv6 filter.
